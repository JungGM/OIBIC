# 공식 첫 제출 이후 개선 실험

이 문서는 실행 순서에 따른 연구 기록이다. 각 절의 채택 판단은 해당 실험에 대한 판단이며, 후속 실험까지 모두 독립 미사용 검증이라는 뜻이 아니다.

실험일: **2026-11-02~03**. 11월 2일 확인한 공식 제출은 정기명 6,441,109,123원, 김수완 6,430,100,536원, 이동준 6,426,522,590원이다. 사용자가 각 제출의 모델 소유자를 확인했다. 공식 평가는 동일한 2025-06~2026-05 전체 기간이다. 서로 다른 그룹을 포함한 시스템 전체 점수이며 개별 발전소 모델만의 우열을 뜻하지 않는다. 11월 3일 신규 점수·순위를 조회한 기록은 아니다.

확인 당시 학부생 부문 태양광신도는 57위였다. 7위는 6,457,350,425원, 1위는 6,467,245,638원이다. 점수 차이는 각각 16,241,302원, 26,136,515원이다. 순위는 변동 가능하다. 서버 점수는 현황 파악에만 사용하며 여러 제출로 숨은 정답에 맞추는 탐색을 하지 않는다.

## 오차 진단과 변경 이유

기상 실측 정답이 없는 상태에서 별도의 '기상예보 오차 정답 모델'을 학습했다고 주장하지 않는다. 제공사 간 불일치·예보 수정량·날짜 안의 변동을 발전량 예측의 설명변수로 사용한다. 발전량 잔차에는 예보 오차 외에도 설비·운영·측정 요인이 섞일 수 있어 이를 개별 원인으로 식별한 결과는 아니다.

기존 3~5월 검증에서 11~15시의 벌금 비중은 각각 82.40%, 79.32%, 79.77%였다. 예측값을 고정한 상태에서 전체 발전소 오차의 절댓값은 모든 두 그룹 배치의 오차 하한이다. 이 하한과 현재 벌금의 차이는 3.96%, 2.34%, 1.75%였다. 따라서 그룹 탐색만으로 큰 폭의 개선을 기대하기보다 예측 오차 자체를 먼저 줄인다. 이 수치는 공식 평가연도의 개선 상한이 아니라 해당 로컬 기간의 진단이다.

1. **155개 특징의 새 LightGBM.** 기존 125개에 30개를 추가했다. 6개 시간 내 태양 위치 표본의 평균, 일조 비율, 운량/UV의 변화·변동·태양고도 가중 평균, 제공 예보의 적설/융설, 기온·풍속 결합, 이슬점 차이와 돌풍 차이다. 전부 같은 대상일의 제공 예보 안에서 계산한다.
2. **비용을 반영한 학습.** 설비용량 × 과거 SMP × 시간대 가중치로 용량당 발전량의 L2 손실을 가중한다. 개별 발전소 모델의 학습 목적을 정산 손실 쪽으로 이동시키는 대리목적이며, 공식 그룹 절대오차를 정확히 최적화한다는 주장은 하지 않는다. 실제 목표일 SMP는 특징에 넣지 않는다.
3. **그룹 오차 보정.** 과거 시간 외 예측으로 그룹별 배율, 시간대별 축소 배율, 정규화된 중앙값 잔차 회귀를 비교한다. 미래 기간 전체 통계로 정규화하지 않고 적합 기간에서만 결측 대체·평균·표준편차·회귀계수를 정한다. 수정량은 기존 예측의 ±12%로 제한하며 0 예측에서 발전량을 만들어 내지 않는다.
4. **기존 앙상블과 혼합.** 새 모델 비중 0/25/50/75/100%를 비교한다. 기존 모델을 남기는 비중 0도 후보에 포함한다. 그룹은 동일하게 고정해 모델 개선과 구성 변경 효과를 혼동하지 않는다.

## 근거와 적용 범위

- [지역 계층 태양광 예측 연구](https://arxiv.org/abs/2403.01653)는 개별·집합 정보를 함께 활용하는 근거다. 해당 HTCNN을 재현한 것은 아니며 대회에서 없는 과거 평가 발전량을 입력하지 않는다.
- [QuantileRegressor 문서](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.QuantileRegressor.html): 중앙값 회귀와 L1 정규화를 이용한다. 그룹별 절대오차 정산에 맞춰 과거 가격을 가중치로 사용한다.
- [LightGBM 매개변수](https://lightgbm.readthedocs.io/en/stable/Parameters.html): 기존 설치 버전의 회귀 목적과 결정적 실행 설정을 고정한다.
- [예측 결합 연구 검토](https://arxiv.org/abs/2205.04216): 서로 다른 예측의 결합은 하나의 모델 선택 위험을 줄이는 근거다. 혼합 자체가 개선을 보장하지 않으므로 이후 기간에서 확인한다.

## 검증 설계

새 모델은 2023-03~2025-02의 최대 24개월, 정답 상한 2025-02-28 17:00으로 학습한다. 보정기는 기존 모델의 2024-07~2025-02 시간 외 예측을 사용한다. 7~12월에는 기존과 동일한 225개소 고정 코호트의 완전 관측 시각, 1~2월에는 253개소 완전 관측 시각을 사용한다. 부분 코호트를 전체 VPP 점수로 부르지 않는다.

3월에서 후보를 선택해 파일로 고정한 다음 4월에 한 후보만 채택 판단한다. 4월 벌금 1% 이상 감소 및 3일 블록 부트스트랩 평균 절감액의 90% 구간 하한이 양수여야 한다. 5월 결과도 악화하지 않아야 새 제출 파일 생성 단계로 넘어간다. 3·4·5월 비교는 각각 737·713·737시간, 동일 253개소·그룹·정산식이다. 누락 정답을 0으로 채우지 않는다.

이 기간들은 이전 연구와 이번 진단에서 이미 확인했다. 이번 실험도 **새로운 미사용 홀드아웃이 아니다**. 후보를 여러 번 바꿔 같은 검증기간에 맞추는 선택 편향과 계절 일반화 한계가 남는다. 합격은 로컬 증거이며 공식 순위 상승 확약이 아니다.

## 2차 실험: 계절 전체 비교

1차에서 계절에 따라 결과가 달라진 뒤 추가한 탐색이다. `improvement_seasonal.py`가 2024년 7월과 2025년 1월 예측시점 직전까지 각각 새 모델을 학습하고 기존의 7~12월/1~2월 검증과 같은 행에서 비교한다. 과거 3~5월 결과를 이미 보았으므로 연구 전체의 독립 시험이라고 부르지 않는다.

## 앞으로의 우선순위

1. **팀원 모델의 시간 외 발전소별 예측 확보 후 결합 검증.** 공식 점수가 낮은 모델이라도 우리 모델과 다른 날 틀리면 도움이 될 수 있다. 공개 2024 설정만으로 2025~2026 실제 제출 모델의 잔차 상관을 알 수 없다. 실제 제출 버전·학습 마감·설정 해시와 같은 기간의 시간 외 예측을 먼저 맞춰야 한다. 근거 없이 세 제출 CSV를 평균하지 않는다.
2. **집합 오차를 직접 학습하는 손실.** 이번 비용가중 개별 L2는 공식 그룹 L1의 대리목적이다. 개별 정확도 개선이 그룹 정산 개선으로 이어지지 않는 부분을 다루는 다음 가설이다. 누락 실적이 많은 과거의 부분 패널을 전체 정답으로 취급하지 않는 별도 실험 설계가 필요하다.
3. **여름 구름 변화·계절 일반화.** 이번 후보는 여름 검증에서 악화했다. 트리 수나 특징을 무조건 늘리는 것보다 과거 시점에서 고정한 계절별 모형·가중치의 시간 순 검증을 우선한다. 평가연도 전체 예보 통계로 계절별 가중치를 고르면 안 된다.

위 우선순위는 다음 연구 가설이며 이번에 구현·검증한 성능 향상으로 표시하지 않는다. 공식 데이터의 평가 정답은 없으므로 예상 공식 점수나 예상 등수를 만들어 제시하지 않는다.

## 3차 실험: 그룹 오차를 포함한 추가 부스팅

2차 후보의 작은 개선에 그치지 않고 우선순위 2를 실제 실험으로 구현했다. `group_loss_experiment.py`는 비용가중 LightGBM에 250개 트리를 추가하며 개별 용량당 제곱오차 25%와 그룹 용량당 오차의 pseudo-Huber 손실 75%를 함께 줄인다. 기존 155개 특징을 유지하고 새 트리는 31 leaves, learning rate 0.025, L2 규제 20으로 고정한다.

정답을 실제로 관측한 발전소만 그룹 오차에 넣으며, 그 관측 용량이 원래 그룹 용량의 80% 미만인 그룹·시각은 개별 손실만 사용한다. 누락 실적을 0으로 만들지 않는다. 부분 관측 집합과 전체 집합의 차이는 여전히 대리목적의 한계다. 가격 가중치는 과거 SMP×k이며 미래 실제가격은 특징에 들어가지 않는다.

관측 발전소의 용량당 오차를 e_i, 용량 가중 그룹 평균 오차를 E_g라 하면, 손실은 Σ_i w_i[(1-λ) e_i²/2 + λ δ²(√(1+(E_g/δ)²)-1)]이며 λ=0.75, δ=0.05다. 공유된 그룹 오차에 대한 기울기를 계산하고 그룹 간 교차항을 다루기 위해 Hessian의 대각 상한을 사용한다. 수치 미분으로 기울기와 상한을 검증한다. 이는 공식 그룹 절대오차의 매끄러운 대리목적이며 공식 정산식을 그대로 학습하는 것은 아니다.

이전 두 실험의 실패를 본 뒤 추가한 탐색이라는 사실을 기록한다. 계절 선택 구간과 4월 안정성·5월 비악화 조건을 유지하며 참조 그룹을 고정한다. `group_loss_experiment.py --stage train/evaluate/produce --data ...`로 재현한다. 결과는 `_local/improvement_v5_group_loss/`, 채택되면 제출 후보는 `제출/improved_v5/`에 생성한다. [LightGBM 사용자 정의 목적함수 API](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.train.html)를 사용한 자체 구현이다.

## 4차: 11.03 독립 XGBoost 재현

[고정한 공개 소스](https://github.com/JungGM/OIBIC/tree/7b956c7/11.03)의 52개 특징·17시 예보·300개 트리·깊이 8·학습률 0.03·min_child_weight 100·L2 규제 30을 그대로 사용했다. 2021년 이후의 실제 관측 실적을 각 학습 마감까지 사용하며, 가격은 과거 학습 가중치에만 넣는다. 공식 XGBoost 논문은 [Chen and Guestrin, 2016](https://arxiv.org/abs/1603.02754)이다. 이 논문은 사용한 부스팅 방법의 출처이며 해당 대회 설정이나 개선 수치의 근거는 로컬 재현 실험이다.

`compact_xgb_experiment.py`는 코드·특징 목록 해시를 확인하고 2024-07, 2025-01, 2025-03 시점에서 각각 재학습했다. 학습 행은 1,201,826 / 1,739,342 / 1,890,845개다. 특징은 float32, 용량당 정답은 float64이며 용량당 정답을 0~1.2로 제한하고 태양고도 0 이하 예측은 0으로 둔다. 저장 모델 재로딩 예측은 모든 검증 예측 행에서 정확히 일치했다.

7~2월에서 기존 모델 25% + 새 XGBoost 75%가 선택됐으며 정규화 손실은 0.967502였다. 하지만 봄 구간은 다음과 같다. 모두 기존과 같은 253개소·실적 시각·참조 그룹·정산식을 사용한다. 학습 기간과 특징의 변경까지 포함한 시스템 비교다.

| 구간 | 시간 | 기존 벌금(원) | 혼합 후보(원) | 벌금 감소율 |
|---|---:|---:|---:|---:|
| 2025-03 | 737 | 12,972,597.63 | 12,440,316.65 | +4.103% |
| 2025-04 | 713 | 17,449,032.11 | 18,313,847.71 | -4.956% |
| 2025-05 | 737 | 21,525,804.53 | 21,751,063.55 | -1.046% |

4월 평균 일별 절감액 90% 구간 하한은 -53,331.74원/일이다. **4차 후보도 미채택**이며 생산 재학습·CSV 생성·공식 제출을 하지 않았다. 기존 모델과 새 모델의 낮 시간 그룹 잔차 상관은 3~5월 각각 0.918 / 0.950 / 0.962였다. 새로운 특징 수와 긴 학습 이력만으로 오차의 상호 보완이 확보되지 않았다.

공개 `11.03` 문서의 2025-01~05 개선은 다른 V1 모델을 기준으로 3,624시간에서 계산된 값이다. 우리 모델은 3월에 재학습하며 월별 마지막 7시간을 제외한 기존 평가 행을 사용한다. 따라서 공개 개선율을 우리 모델 대비 개선율로 바꿔 부를 수 없다.

```powershell
py JungGM/compact_xgb_experiment.py --stage train --data "공식 데이터 폴더"
py JungGM/compact_xgb_experiment.py --stage evaluate --data "공식 데이터 폴더"
py JungGM/compact_xgb_experiment.py --stage produce --data "공식 데이터 폴더"
```

캐시는 `_local/improvement_v6_compact_xgb/`에 보존한다. `produce`는 채택 조건이 거짓이면 파일을 만들지 않고 종료한다.

## 5차: 이동준 공개 LightGBM·CatBoost 방법의 재학습

`team_pair_experiment.py`는 `lgbm_catboost_2024/src/features.py`와 `configs/final_model.json`의 SHA256을 고정하고 직접 읽는다. 기존 폴더를 수정하거나 모델 파일을 덮어쓰지 않는다. 출력은 전부 `JungGM/_local/improvement_v7_team_pair/` 안에 둔다.

- **특징 160개:** 제공 예보 10·17시, 제공사 간 차이, 날짜 안의 변화·분산, 적설/융설/열·풍속 결합, 제공 좌표로 계산한 pvlib 태양 위치와 시간 내 6개 표본이다. 외부 기상 API나 실제 좌표 복원은 사용하지 않는다. [pvlib 태양 위치 API](https://pvlib-python.readthedocs.io/en/stable/reference/generated/pvlib.solarposition.get_solarposition.html)를 사용한다.
- **LightGBM:** L1 손실, 484개 트리, 31 leaves, 학습률 0.04, 최소 잎 표본 200, L2 규제 5, 특징 표본비 0.85다.
- **CatBoost:** MAE 손실, 600개 트리, 깊이 6, 학습률 0.04, L2 규제 5, 관측소 코드 두 개를 범주형 변수로 사용한다. [CatBoost 논문](https://arxiv.org/abs/1706.09516)은 알고리즘 출처이며 이 실험이 모든 논문 설정을 재현했다는 뜻은 아니다.
- **결합:** 팀원 공개 설정의 LightGBM 50% + CatBoost 50%를 먼저 고정한다. 그 결합 모델과 우리 기존 앙상블의 혼합 비중 0/25/50/75/100%만 기존 7~2월 선택 구간에서 비교한다. 4·5월 결과를 보고 비중을 재선택하지 않는다.

팀원 방식대로 관측된 비음수 실적 전체를 사용하므로 야간도 포함하며 용량당 정답을 1.2에서 자르지 않는다. 과거 SMP×시간대 가중치×용량을 float32 가중치로 사용한다. **시간 순 비교를 위한 변경점은 학습창**이다. 공개 코드의 2022~2023 고정 학습 대신 각 2024-07/2025-01/2025-03 시작 직전 최대 24개월을 사용하고, 마감은 전날 17시로 통일한다. 따라서 공개 방법의 시점별 재학습이지 팀원의 실제 공식 제출 바이너리 복제는 아니다.

특징 캐시는 전체 24시간 대상일에서 만든 뒤 학습 실적만 마감으로 자른다. 미래 실적·미래 SMP를 특징에 넣지 않는다. pvlib 0.16.1와 CatBoost 1.2.10은 팀원 버전과 같고, numpy/pandas 등은 기존 JungGM 환경을 유지했다. 원래 팀원 환경 전체의 바이트 단위 재현이라고 주장하지 않는다.

```powershell
py -m venv --system-site-packages JungGM/_local/team_env
JungGM/_local/team_env/Scripts/python.exe -m pip install -r JungGM/requirements-team.txt
JungGM/_local/team_env/Scripts/python.exe JungGM/team_pair_experiment.py --stage prepare --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/team_pair_experiment.py --stage train --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/team_pair_experiment.py --stage evaluate --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/team_pair_experiment.py --stage produce --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe -m unittest discover -s JungGM -p "test_*.py"
py JungGM/audit_improvement.py --data "공식 데이터 폴더"
```

평가에는 먼저 기존 `pipeline.py`로 생성한 동일 기준 모델의 시간 외 예측이 필요하다. 기존 재현 절차는 `README.md`를 따른다. 학습은 모델마다 별도 프로세스로 실행해 메모리를 회수하며, 코드의 `--stage fit --part ... --model ...`로 완료 지점부터 재개할 수 있다. 그룹은 기존 G1/G2로 고정한다. 채택 기준을 통과한 경우에만 `제출/improved_v7/`에 새 CSV를 생성한다.

계절 선택에서 새 모델 비중이 0%이면 선택 시스템은 기존 모델과 같고 개선율은 정확히 0%다. 따라서 변경하지 않은 1% 채택 기준을 통과할 수 없으며, 쓰이지 않을 봄 모델의 추가 학습은 생략한다. 이때 새 모델 단독 봄 점수는 `null`, `standalone_development_evaluated`는 `false`로 기록해 미학습·미측정 결과를 만들어 넣지 않는다. 0% 이외의 비중이면 반드시 실제 봄 예측을 생성해야 평가가 진행된다. 이 운영상 생략은 겨울 평가가 끝나기 전에 구현했으며 혼합 후보·선택 목적·채택 기준을 바꾸지 않는다.

## 6차: 기존 모델·팀원 LightGBM·CatBoost의 성분별 결합

5차의 고정 50:50 비교와 별도로, `component_ensemble.py`에 세 전문가의 볼록 결합 15개를 선언했다. 각 비중은 0/25/50/75/100%이며 합은 100%다. 선언 시점에는 5차의 여름·가을 고정 결합 결과를 봤지만 겨울 CatBoost가 아직 학습 중이었다. 5차의 결과나 혼합 규칙을 뒤바꾸지 않고 별도 6차 탐색으로 기록한다.

이유는 두 새 모델 중 하나만 기존 모델의 오차를 보완할 가능성이 있기 때문이다. 반드시 50:50으로 묶으면 그 가능성을 놓칠 수 있다. 그렇다고 성능 향상을 가정하지 않으며, 7~2월 선택과 같은 4월 안정성·5월 비악화 기준을 적용한다. 학습 설정·특징·마감은 5차와 동일하다. 이미 학습한 모델이 있으면 해시와 마감을 확인한 뒤 재사용하고, 실제로 선택된 성분만 추가 학습한다. 모든 봄 평가 자료는 이미 여러 탐색에 사용한 역사 자료다.

```powershell
JungGM/_local/team_env/Scripts/python.exe JungGM/component_ensemble.py --stage declare --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/component_ensemble.py --stage select --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/component_ensemble.py --stage evaluate --data "공식 데이터 폴더"
JungGM/_local/team_env/Scripts/python.exe JungGM/component_ensemble.py --stage produce --data "공식 데이터 폴더"
```

6차 기록은 `_local/improvement_v8_components/`, 채택 시 제출 후보는 `제출/improved_v8/`다. 원본 공식 제출을 덮어쓰거나 서버로 자동 제출하지 않는다.
