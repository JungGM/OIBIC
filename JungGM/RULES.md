# 대회 규정과 구현 경계

확인일: **2026-10-29 KST**. [공식 대회 페이지](https://dataen.ai/en/challenge/2026)가 연결하는 현재 공개 클라이언트 리소스의 태양광 VPP 트랙과 사용자 배포 `README.md`, `baseline.py`를 대조했다. 로그인 후 게시판의 모든 답변이나 별도 문제정의서 개정본까지 확인한 것은 아니다. 제출 전 새 공지나 문제정의서 변경이 있으면 다시 반영해야 한다.

## 공식 조건

- `sites.csv`의 253개소를 빠짐없이 정확히 한 그룹에 넣는다. 두 그룹은 G1/G2이며 각각 설비용량 합계가 20,000 kW 이상이다. 평가기간 내 구성은 고정한다.
- 예측 대상은 2025-06-01 01:00~2026-06-01 00:00 KST의 8,760시각이다. 각 그룹이 같은 시간축을 사용하므로 forecast 데이터 행은 17,520개다.
- 시각은 KST, 1시간, 우측닫힘이다. 01시는 00~01시 발전량이며 00시는 앞 운영일의 마지막 시간이다.
- 예측 기준시점은 대상일 전일 17:00 KST다. 그 뒤 생성된 발전실적·기상실측 등은 입력으로 사용할 수 없다.
- 제공된 전일 10시와 17시 예보는 모두 사용할 수 있다. 평가기간에는 발전실적·기상실측이 제공되지 않는다.
- 외부 데이터와 외부 데이터로 학습된 모델은 사용할 수 없다. 익명 좌표 복원·재식별 시도도 금지다.
- 평가 예보에 일부 결손이 있어도 해당 시각은 제출·채점 대상에 남겨야 한다.
- 사용 언어는 Python/R이다. VPP 트랙 제출 제한은 하루 3회, 전체 20회다. 다른 트랙의 하루 10회 문구와 구분한다.
- composition·forecast 두 파일을 함께 제출한다. CSV 또는 Parquet, 파일당 20MB 이하이며 형식 실패도 제출 횟수에 포함된다. 공개 페이지의 접수 마감은 2026-11-13 23:59:59다.

## 이번 구현에서 지키는 정보 경계

최종 모델의 학습 정답은 **2025-05-31 17:00 KST 이하**로 제한한다. 배포 학습 실적의 마지막 2025-06-01 00:00까지 모두 읽어 학습하면 첫 대상일의 예측시점보다 늦은 정답이 포함되기 때문이다. 이 경계는 전일 17시 조항을 보수적으로 적용한 구현 결정이다. 시간순 로컬 검증에서도 같은 제한을 적용한다.

개발 선택의 첫 예측 시작점은 2024-07-01 01:00, 학습 끝은 2024-06-30 17:00이다. 둘째는 2025-01-01 01:00, 학습 끝은 2024-12-31 17:00이다. 원칙적으로 각 시작점 직전 24개월을 사용하며 최근 모델 후보는 12개월을 사용한다. 3월 그룹용 잔차는 2025-02-28 17:00까지 재학습한 모델로 만든다. 4월 그룹 채택과 5월 고정 감사 이후 최종 생산 모델을 재학습한다.

평가기간 예보는 해당 대상일에 제공된 발행분만 특징 계산에 사용한다. 여러 시간 범위 특징을 만들더라도 다음 대상일에 새로 발행되는 예보를 앞 대상일의 입력으로 섞지 않는다. 평가기간의 발전량을 추정해 정답으로 재학습하거나 평가 실측을 만들어 쓰지 않는다.

태양기하는 제공된 익명 좌표와 시각으로만 계산한다. 외부 지도·기상 API·발전소 명부·사전학습 가중치를 받는 경로를 두지 않는다. 논문의 알고리즘을 참고하는 것과 논문에 쓰인 외부 데이터를 가져오는 것을 구분한다.

## 데이터 처리 주의사항

- 없는 발전실적 행은 결측이다. 0으로 채우거나 모델 예측을 정답으로 삼지 않는다. 관측된 발전량 0은 일괄 제거하지 않는다.
- 전체 발전소×제출시각 격자를 유지한다. 예보 결손 때문에 예측행이 사라지는 inner join이나 행 삭제를 피한다.
- A 풍속은 m/s, B 풍속은 km/h다. 혼합 파생 특징을 만들 때 환산한다. A 강설은 mm, B 강설은 cm다.
- A 예보 습도 104는 원본 값이다. 정의를 확인하지 않은 값에 일괄 sentinel 규칙을 적용하지 않는다.
- 학습 SMP에는 `k`가 없다. README에 따라 종료시각 11~15시는 3, 나머지는 1이다. 공식 시간축과 평가 `k`는 제공 파일을 사용한다.
- 완전 실적이 없는 시각에서 결측 발전소를 0으로 채운 전체 그룹 점수를 만들지 않는다. 완전 관측 점수와 부분 관측 진단을 명확히 구분한다.

## 검증 점수의 범위

2024년 7~12월은 전체 구간 실적 보유율 95% 이상인 **하나의 고정 코호트**를 사용하고 그 코호트 전원의 실적이 있는 시각만 채점한다. 현재 제공 자료에서는 225개소이며 전체 253개소의 공식 VPP 점수가 아닌 부분 대리목적이다. 2025년 1~2월(마지막 2월 28일 17시)은 전체 253개소의 동시 실적 시각을 사용한다.

모델 선택은 각 월의 적응 기준선 대비 비용 비율로 정규화한다. 2024년 계절 대리목적 블록에 50%, 2025년 겨울 전체 관측 블록에 50%를 주고 각 블록 안의 월은 같은 비중으로 둔다. 최대 3개 모델, 0.1 간격, 0 이상·합계 1의 앙상블을 비교한다. 이 혼합 선택값을 공식 점수라고 표시하지 않는다.

비교 기준선은 공식 baseline 구조를 가져오되 학습시점 경계·기간과 B 풍속 단위를 맞춘 변형이다. 강화 후보 6개는 용량 가중치로 학습하고 기준선은 비가중이다. 결과를 보고할 때는 이 후보 범위와 기준선의 수정 사항을 함께 명시한다.

2024~2025년 자료는 이전에도 검토했으므로 이번 5월 감사를 연구 전체의 미사용 홀드아웃이라고 부르지 않는다. 이번 실행 안에서 모델·그룹 선택을 고정한 후 감사한다는 의미로 사용한다. 상세 방법과 논문 적용 범위는 [PAPER_METHOD.md](PAPER_METHOD.md)에 기록한다.

## 파일과 공개 저장소

사용자 요청에 따라 이번 소스·문서는 `oibc/JungGM` 경로에 모은다. 학습 캐시·모델·발전소별 예측은 `JungGM/_local`, 실제 제출용 `composition.csv`와 `forecast.csv`는 `JungGM/제출`에 만든다. 두 디렉터리의 산출물은 공개 Git에 올리지 않도록 제외한다. 공개 문서에는 원본 데이터 행이나 발전소별 예측값을 복사하지 않는다.

원본 자료는 기존 위치에서 읽기만 하며 외부 서비스로 전송하지 않는다. 로컬 처리와 공개 제외는 이 작업의 데이터 보호 원칙이다. `.gitignore`는 Git 추가를 제한할 뿐 다른 동기화 프로그램이나 이미 추적 중인 파일까지 차단하지 않으므로, 공개 전 추적 상태도 확인해야 한다.

`composition.csv` 필수 열은 `site_id,group`, `forecast.csv`는 `group,ts,forecast_kwh`다. 제출값은 유한한 0 이상 수치이며 `ts`에 KST 타임존을 포함한다. composition은 헤더 포함 254행, forecast는 헤더 포함 17,521행이다. 개수뿐 아니라 정확한 모든 키, 용량, 중복·누락, 시간범위도 검사한다.

이번 작업은 로컬 제출물 생성까지이며 공식 서버 제출을 실행하지 않는다. 검사 통과는 파일 구조와 구현한 제약의 통과를 뜻한다. 공식 점수·서버 접수 성공·규정 전체 준수에 대한 주최 측 확인을 대신하지 않는다.
